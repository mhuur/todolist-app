# todolist-app

**MyTodo** — app web personnelle (todo + deadlines + CRM fournisseurs/produits + CRM projets/technos). **Mono-utilisateur** (Google Auth, doc Firestore `users/{uid}`). **Production**, page statique servie depuis `main` (GitHub Pages / équivalent).

## Stack & structure

- **Tout dans `index.html`** (monolithique, pas de build, pas de tests, pas de lint). Majorité en **vanilla JS** (un gros `<script>`) ; l'onglet **Projet** est un composant **React** dans un `<script type="text/babel" id="flux-src">` compilé en navigateur (React+Babel lazy-loadés).
- **Firebase v8 compat** chargé via CDN (`firebase.auth()`, `db.collection(...)`). **Ne pas migrer vers v9 modulaire.**
- **Cache local** : `localStorage["todolist-data-v3"]` (constante `SK`). Changer le suffixe casse tous les caches.
- Fichiers : `index.html`, `README.md`, `LICENSE`, `.gitignore`, plus les **4 fichiers de l'app installable** (`manifest.json`, `sw.js`, `icon-192.png`, `icon-512.png` — août 2026). Rien d'autre. ⚠️ Ces 4-là **ne peuvent pas** être inlinés dans `index.html` : un service worker doit être un fichier servi depuis l'origine (portée), et Chrome exige manifeste + service worker + icône ≥ 192 px pour proposer l'installation. C'est la seule exception au mono-fichier.
- **App installable (PWA)** : `display:"standalone"` → une fois ajoutée à l'écran d'accueil, l'app s'ouvre **sans le bandeau du navigateur** (c'était la demande de Romain, août 2026 : « on a l'impression d'être encore sur navigateur »). `theme_color:#ffffff` = la barre d'état Android prend la couleur de l'en-tête blanc de l'app. `sw.js` est **réseau d'abord pour la navigation** : `index.html` n'est jamais servi depuis le cache tant que le réseau répond, sinon un push sur `main` ne serait plus visible ; le cache ne sert qu'au hors-ligne, et les requêtes tierces (Firebase, Google Fonts, CDN React/Babel) ne sont pas interceptées. Le service worker n'est enregistré **qu'en HTTPS** (pas en `py -m http.server`) pour ne jamais brouiller le développement local. L'entrée « Installer l'application » du menu du rond d'initiales n'apparaît que si Chrome émet `beforeinstallprompt` (`pwaInstall`/`pwaPrompt`) — elle disparaît d'elle-même une fois l'app installée, et n'existe pas sur iOS (installation manuelle via Partager → Sur l'écran d'accueil).

à droite un filtre **Personne** (vue Tâches, mono-projet) et une **pastille 💧 « X pour aujourd'hui »** cliquable (état transient `todayView`). *(Le segment `Tâches | Planning | Notes` a été RETIRÉ : Planning est un **onglet dédié** de la sidebar, la sous-vue Notes projet supprimée ; `projView` vaut toujours `'todo'`.)* Des **onglets de statut** (Tous/En cours/À faire/En attente = `projStatusTab`, transient) filtrent les vues Tâches ET Aujourd'hui — ⚠️ **onglets de statut ET filtre Personne MASQUÉS partout depuis sept. 2026** (Romain ne s'en sert pas) : deux règles CSS globales `#flux-root div:has(>.ek-htab)` / `#flux-root [data-fchip]` à côté de `.ek-htab`, code JSX et état intacts (`projStatusTab` vaut donc toujours `'all'`, `projPersonFilter` toujours vide) ; les retirer les fait réapparaître sur ordinateur, le bloc téléphone gardant ses propres règles. **▸ Vue Tâches** (`renderProjTaskView`, défaut) : **toutes les tâches du périmètre** (tous projets si `allMode`, sinon projet sélectionné), rendues en **lignes façon Aujourd'hui** (`renderTodayRow`, avec **numéro + nom du projet devant** ; VM `tvm`), **groupées par statut** (En cours → À faire → En attente → Terminées, VM `projTaskGroups` dans `buildVM`). Groupes **vides masqués** (révélés pendant un glisser, comme zone de dépôt — jamais insérés en DOM au dragstart sinon le drag natif est annulé). Le groupe **« Terminées » est un volet REPLIÉ par défaut** (sept. 2026) : en-tête `.ek-gfold` cliquable (chevron `.cv/.op` + compteur), lignes rendues seulement une fois déplié ; état **transient** `doneOpen` (runtime + `_enterProject` → se replie à chaque session et à chaque changement de projet). **Ajout** = **champ fin** en haut (`renderThinAdd('proj')`) créant au **statut de l'onglet actif** (À faire par défaut). **Drag** : `reorderTaskAny` réordonne dans **l'ordre du tableau du projet** (persistant) et adopte le statut du groupe de dépôt ; en `allMode`, déposer une tâche dans un autre projet ne change que son statut. **▸ Vue Aujourd'hui** (pastille 💧 → `todayView`) : **cross-project, tous projets** (ignore le filtre projet). Contenu = tâches **flaggées `today`** (goutte 💧 par ligne, `toggleToday`) **+ auto-alimentées** : **programmées** (`due ≤ aujourd'hui`, hors `done`/`wait`) et **à relancer** (`wait` + `relance ≤ aujourd'hui`) ; une tâche **validée depuis Aujourd'hui reste visible (cochée, dans le groupe « Terminé ») jusqu'au lendemain**, puis disparaît. Mécanique : `toggleDoneAny`/`setStatus` (les 2 chemins de complétion réellement câblés ; `toggleDone` est mort) posent `doneAt` et **conservent `today:true` + la position `todayOrder`** SI la tâche faisait partie d'Aujourd'hui au moment de la validation (`_taskInToday` = flag today OU programmée/relance due) — sinon comportement historique (retire `today`+`todayOrder`). `todayTasks` réinclut ces tâches tant que `today && doneAt=aujourd'hui` (`_doneAtToday`, jour local). Le passage au lendemain est **automatique à l'affichage** (`_doneAtToday` recalcule `new Date()` à chaque render) ; `_purgeStaleTodayDone` (appelé en `componentDidMount`) nettoie en plus le flag `today`/`todayOrder` résiduel des done d'un autre jour. Le groupe « Terminé » n'apparaît que sous l'onglet « Tous » et est **replié par défaut** (sept. 2026 — même en-tête cliquable `renderDoneLabel` et même état transient `doneOpen` que le groupe « Terminées » de la vue Tâches) ; la pastille « X pour aujourd'hui » (`todayTotal`) **exclut** les validées (compte le restant à faire). Mêmes lignes (`renderTodayRow`), **groupées par statut** (À relancer → En cours → À faire → En attente, `todayGroups`), filtrées par les **mêmes onglets `projStatusTab`**. **Ajout** = champ fin (`renderThinAdd('today')` → `addTodayTaskStatus`) créant une tâche `today:true` **sans projet** (bac réservé `__inbox` « Sans projet », créé à la volée par `_withInbox`, masqué du sélecteur + auto-purgé quand vide) ; le projet se (ré)assigne **par ligne** via la cellule Projet devenue picker (recherche + « Sans projet » + créer-si-absent → `moveTaskToProject`/`createProjectForTask`). **Drag** : `reorderToday` réordonne dans `todayOrder` **et propage au tableau projet** (sept. 2026) : la tâche glissée est réinsérée dans son projet avant/après sa voisine du même projet dans le nouvel ordre ; « À relancer » reste triée par date de relance. **Invariant d'ordre Projet ↔ Aujourd'hui (sept. 2026)** : deux tâches d'un **même projet** ont le même ordre relatif dans les deux vues — `todayOrder` ne pilote que l'**entrelacement entre projets** (les « slots ») ; une **normalisation à l'affichage dans `todayTasks`** (champ `ai` = indice dans le tableau projet) redistribue les tâches de chaque projet sur leurs positions dans l'ordre projet, si bien qu'un drag fait dans la vue Tâches (`reorderTaskAny`) se reflète dans Aujourd'hui sans aucune propagation. Exceptions assumées : groupes « À relancer » (tri par date) et « Terminé » (tri par `doneAt`). ⚠️ **Il n'y a PLUS d'onglet « Aujourd'hui » séparé dans la sidebar, ni de prop `todayOnly` active** (elle vaut toujours `false` ; un `S.tab` sauvegardé `"today"` est redirigé vers `"flux"`) : Aujourd'hui est une **sous-vue de Projet**. **Lignes (`renderTodayRow`, communes aux 2 vues)** : case (lime), pastille statut + menu, cellule Projet (numéro+nom, clic = picker), titre éditable inline, colonne échéance (`due` « Faire le », ou date de **`relance`** en corail pour les `wait` — popover ouvert auto au passage en *En attente* via `setStatus`), chip Personne, **goutte 💧** (bleue pleine = déjà dans Aujourd'hui → clic pour retirer ; grise au survol = clic pour ajouter, `toggleToday`), **menu ⋮** (façon Google Tasks, transient `rowMenuId`, fermé au clic hors `[data-rowmenu]` par `_docClick`) contenant Ajouter une sous-tâche / Note (= panneau détail) / Supprimer (`askDelete`→modale→`confirmDelete`). **Refonte août 2026** : chevron, puce `N/M`, boutons note et corbeille **retirés de la ligne** (remplacés par le menu ⋮) ; les **sous-tâches sont toujours dépliées** dès qu'il y en a (plus de repli ; `openSubs` supprimé). **Ajout de sous-tâche** : uniquement via le menu ⋮ (plus de champ « + Ajouter » permanent) — un champ vide apparaît sous les sous-tâches (transient `subAddId`), Entrée ajoute et garde un champ vide pour enchaîner, Échap/blur (clic ailleurs) le fait disparaître. ## Pièges spécifiques

- **Modèle `S.priceLib.quotes[]`** : un devis porte `lines:[{id,product,values}]` (N équipements sous 1 réf/dossier) + `projet` (texte). Les champs legacy `product`/`values` au niveau devis sont un **miroir de la 1re ligne** (compat tableau, pas encore retirés). Migration additive idempotente via `plMigrateLines` (appelée par `plEnsure`). Champs texte de saisie : `oninput` ne re-render JAMAIS (suggestions via combobox `.pl-combo-static` + CSS `:focus-within`).
- **Persistance à 6 endroits** : tout nouveau champ ajouté à `S` doit être propagé dans **toutes** ces zones, sinon perte au reload ou à la sync :
  1. `loadFromCloud` (lecture Firestore)
  2. Écriture cache localStorage juste après le load cloud
  3. Bloc de migration premier login
  4. Fallback `catch` localStorage
  5. `saveToCloudNow` (objet `data`)
  6. `save()` (écriture localStorage)
- **Limite Firestore 1 MB par doc** — `users/{uid}` contient TOUT le state. **Ne JAMAIS stocker d'images en data URL inline** (screenshots de notes/feedback, avatars). `stripImgs()` est appelé avant `set()` mais ne couvre pas tout. Symptôme : `saveToCloudNow` échoue silencieusement → cloud gelé, divergence local/prod.
- **Debounce save 1500 ms sans flush beforeunload** — fenêtre de perte si reload/fermeture < 1.5 s après une modif. À durcir si problème : ajouter un `flushSaveBeforeUnload` (clear `saveTimer` + `saveToCloudNow()` synchrone sur `beforeunload`/`pagehide`).
- **Renames** : un rename de produit doit aussi mettre à jour `S.crm.suppliers[].products`, `S.crm.preferred`, et les clés d'expansion `S.ex` dérivées du nom.
- **`JSON.stringify(x)` injecté dans un attribut HTML `onclick="..."`** : les `"` produits par JSON cassent silencieusement l'attribut (handler jamais installé, aucune erreur console). Toujours wrapper : `onclick="fn(${esc(JSON.stringify(x))})"`. `esc()` transforme `"` → `&quot;`, le parseur HTML décode → la string JS arrive intacte.
- **`<input type="date">` + re-render sur `oninput`** : à chaque keystroke (chiffre du jour/mois/année), `oninput` se déclenche → si on re-render, le widget date du navigateur est réinitialisé entre deux chiffres et la saisie devient impossible. Toujours utiliser `onchange` (déclenché une fois la date complète, au blur). Pareil pour `type="time"` / `type="datetime-local"`.
- **Composant stateful + focus restore = boucle de re-init** : un composant qui (1) maintient un state global (ex. `plCombo={key,query}`), (2) ré-installe son focus en fin de `render()`, et (3) reset son state dans son handler `onfocus` → boucle infinie (re-render → focus restore → onfocus → reset state → re-render…). Garde-fou : l'opération d'**ouverture** doit être idempotente sur la même cible — `function open(key){if(state&&state.key===key)return; state={key,query:""}; reRender();}`. Sans ce guard, le `query` se vide à chaque keystroke ou la perf s'effondre.
- **Firebase v8** (pas v9 modulaire) — garder l'API `firebase.auth()`, `db.collection(...)`. Pas de `import`.
- **Connexion : popup partout, JAMAIS `signInWithRedirect` par défaut** (correctif août 2026). L'app est servie depuis `mhuur.github.io` alors que l'`authDomain` est `totolist-mhuur2.firebaseapp.com` : le flux redirect a besoin du stockage de ce domaine tiers, que les navigateurs **mobiles** bloquent (cookies tiers) → `getRedirectResult()` revient vide, `onAuthStateChanged` reçoit `null`, l'écran de connexion réapparaît et **la connexion boucle à l'infini sur mobile**. `doLogin()` utilise donc `signInWithPopup` sur tous les appareils, avec repli sur `signInWithRedirect` **uniquement** si le popup est bloqué (`auth/popup-blocked`, `auth/operation-not-supported-in-this-environment` — WebView in-app). Ne pas réintroduire de branche `isMobile → redirect`. Le `catch` de `getRedirectResult()` **affiche** l'erreur dans `#login-msg` (avant : avalée silencieusement, d'où un diagnostic impossible) — ne pas le revider. **Correctif structurel si le problème revient** : servir l'app depuis Firebase Hosting (`totolist-mhuur2.web.app`), où `authDomain` = domaine de l'app, ce qui supprime la dépendance au stockage tiers. **Écran de connexion différé (sept. 2026)** : `#login-screen` est masqué par style inline au chargement et n'apparaît que quand `onAuthStateChanged` a répondu `null` — avant, il flashait à chaque rechargement sur téléphone le temps que Firebase restaure la session. Un indice `localStorage["auth-hint"]` (posé à la connexion, retiré à la déconnexion) le fait afficher immédiatement pour un visiteur non connecté ; un petit `<script>` **séparé de l'init Firebase** (pour tourner même si le SDK n'a pas chargé) porte cette logique + un garde-fou à 8 s (`window.__authKnown`, ignoré en `__demoMode`). Ne pas remettre `display:flex` par défaut.
- **Scope Google Contacts (`GC_SCOPE`) demandé sur desktop seulement** : la sync CRM Fournisseurs est un usage desktop, et ce scope *sensible* déclenche 2 écrans de consentement supplémentaires (« Google n'a pas validé cette application », « … veut un accès supplémentaire »). Sur mobile, `gcSyncContacts()` retourne proprement `{ok:false,reason:"no-token"}` et les contacts déjà synchronisés restent lisibles (ils vivent dans `S.crm`, Firestore). Le token contacts est stocké **par appareil** (`localStorage["gc-tok"]`).
- Pas de `bundler`, pas de TypeScript : tout reste en JS plain dans la balise `<script>`.

# CLAUDE.md

Behavioral guidelines to reduce common LLM coding mistakes. Merge with project-specific instructions as needed.

**Tradeoff:** These guidelines bias toward caution over speed. For trivial tasks, use judgment.

## 1. Think Before Coding

**Don't assume. Don't hide confusion. Surface tradeoffs.**

Before implementing:
- State your assumptions explicitly. If uncertain, ask.
- If multiple interpretations exist, present them - don't pick silently.
- If a simpler approach exists, say so. Push back when warranted.
- If something is unclear, stop. Name what's confusing. Ask.

## 2. Simplicity First

**Minimum code that solves the problem. Nothing speculative.**

- No features beyond what was asked.
- No abstractions for single-use code.
- No "flexibility" or "configurability" that wasn't requested.
- No error handling for impossible scenarios.
- If you write 200 lines and it could be 50, rewrite it.

Ask yourself: "Would a senior engineer say this is overcomplicated?" If yes, simplify.

## 3. Surgical Changes

**Touch only what you must. Clean up only your own mess.**

When editing existing code:
- Don't "improve" adjacent code, comments, or formatting.
- Don't refactor things that aren't broken.
- Match existing style, even if you'd do it differently.
- If you notice unrelated dead code, mention it - don't delete it.

When your changes create orphans:
- Remove imports/variables/functions that YOUR changes made unused.
- Don't remove pre-existing dead code unless asked.

The test: Every changed line should trace directly to the user's request.

## 4. Goal-Driven Execution

**Define success criteria. Loop until verified.**

Transform tasks into verifiable goals:
- "Add validation" → "Write tests for invalid inputs, then make them pass"
- "Fix the bug" → "Write a test that reproduces it, then make it pass"
- "Refactor X" → "Ensure tests pass before and after"

For multi-step tasks, state a brief plan:
```
1. [Step] → verify: [check]
2. [Step] → verify: [check]
3. [Step] → verify: [check]
```

Strong success criteria let you loop independently. Weak criteria ("make it work") require constant clarification.

---

**These guidelines are working if:** fewer unnecessary changes in diffs, fewer rewrites due to overcomplication, and clarifying questions come before implementation rather than after mistakes.
